**Proyecto en desarrollo — aún sin funcionalidad completa**

## 🛠️ Cómo contribuir

### ✔️ Flujo de trabajo profesional

1. *Fork* del repositorio:
```bash
git clone https://github.com/loopsociety/loopsociety-forum.git
cd loopsociety-forum
```
2. Crea una rama descriptiva desde `development`, por ejemplo: `feature/login`, `fix/navbar`, `chore/dockerize`:
```bash
git checkout -b fix/navbar
```
3. Trabaja en tu feature o bug.
4. Haz un **Pull Request** a `development`.

### 🧾 Reglas para PR

- Usa **Commits Convencionales**:
  - `feat`: nueva funcionalidad
  - `fix`: corrección de bug
  - `docs`: cambios en documentación
  - `style`: formateo, linting, no afecta lógica
  - `refactor`: reestructura sin cambiar comportamiento
  - `test`: agrega/modifica tests
  - `chore`: tareas de mantenimiento

- **Descripción clara del PR**:
  - Objetivo del cambio.
  - Contexto o issue relacionado (ej: `Closes #12`).
  - Pasos para probar manualmente.

- **Solicita revisión**: al menos *dos revisores* deben aprobar.
- **Rebase o merge actualizado**: evita conflictos al integrar.

## 🤝 Código de conducta

Nos regimos por los mismos valores que grandes empresas tecnológicas: respeto, profesionalismo y crecimiento compartido.

- **Respeto y empatía** en cada interacción.
- **Retroalimentación constructiva** y basada en argumentos técnicos.
- **Diversidad e inclusión** de ideas y estilos.
- **Profesionalismo**: usamos lenguaje claro, estilo neutral y buena redacción.
- **Aprender de errores**: fallar hace parte del proceso, lo importante es mejorar.
